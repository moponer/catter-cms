# 主题开发核心注意事项

> 本文档来自 duocai-blog 主题开发实践教训总结，适用于所有主题开发。

---

## 一、绝对禁止事项

### 1.1 数据与模板解耦（最重要）

```html
<!-- ❌ 错误：硬编码数据 -->
<h1>我的博客</h1>
<p>这是我的个人博客，记录技术和生活</p>
<div style="background: #2D2A4A">深紫色背景</div>

<!-- ✅ 正确：所有数据来自配置 -->
<h1>{{ getConfig "siteTitle" "默认标题" }}</h1>
<p>{{ getConfig "siteDescription" "默认描述" }}</p>
<div style="background: var(--primary)">使用CSS变量</div>
```

**原则：模板中不应该存在任何用户可能想要修改的硬编码内容。**

### 1.2 颜色值规范

```css
/* ❌ 错误：混用硬编码颜色和CSS变量 */
.hero {
    background: #2D2A4A;  /* 硬编码颜色 */
    color: var(--text-primary);
}

/* ✅ 正确：全部使用CSS变量 */
.hero {
    background: var(--primary);
    color: var(--text-primary);
}
```

**原则：所有颜色必须通过CSS变量定义，禁止在CSS或HTML中硬编码颜色值（#xxx、rgb()等）。**

### 1.3 HTML结构完整性

```html
<!-- ❌ 错误：不完整的HTML结构 -->
<div class="hero">
    {{ range .slides }}
    <div class="carousel-slide">
</div>

<!-- ✅ 正确：完整的条件结构和闭合 -->
{{ if .slides }}
<div class="hero">
    {{ range .slides }}
    <div class="carousel-slide">...</div>
    {{ end }}
</div>
{{ end }}
```

**原则：每个模板文件必须有完整的HTML结构，包含 `<!DOCTYPE html>`、`<html>`、`<head>`、`<body>`。**

### 1.4 Go 模板语法正确性

```html
<!-- ❌ 错误：dot和字段之间有空格（会被解析为函数调用） -->
{{ . Excerpt }}
{{ . Category.Name }}

<!-- ✅ 正确：dot紧跟字段名 -->
{{ .Excerpt }}
{{ .Category.Name }}
```

**原则：Go模板中 `.字段名` 必须连写，中间不能有空格。**

### 1.5 CSS动画完整性

```css
/* ❌ 错误：删除动画的关键帧定义 */
.carousel-slide {
    animation: slideShow 8s infinite;
}
/* 缺少 @keyframes slideShow */

<!-- ✅ 正确：动画和关键帧必须同时存在 -->
.carousel-slide:nth-child(1) { animation: slideShow 8s infinite 0s; }
.carousel-slide:nth-child(2) { animation: slideShow 8s infinite 2s; }

@keyframes slideShow {
    0% { opacity: 0; }
    5% { opacity: 1; }
    25% { opacity: 1; }
    30% { opacity: 0; }
    100% { opacity: 0; }
}
```

**原则：每个CSS动画必须同时包含 `animation` 属性和对应的 `@keyframes` 定义。**

## 二、必须遵守的规范

### 2.1 配置项定义

```yaml
# theme.yml - 配置值
config:
  # 博主信息
  authorName: ""
  authorBio: "热爱技术，分享生活"
  authorAvatar: ""
  authorShowStats: true

# configDefinition - 配置定义（后台表单）
configDefinition:
  - section: author
    label: 博主信息
    fields:
      - name: authorName
        type: text
        label: 作者昵称
        default: ""
      - name: authorBio
        type: textarea
        label: 作者简介
        default: "热爱技术，分享生活"
```

**原则：所有用户可配置的数据必须在 `config` 和 `configDefinition` 中同时定义。**

### 2.2 字段类型注册

```
所有在 theme.yml 中使用的字段类型，必须在 FieldRenderer.vue 中注册：

支持的字段类型：
- text、textarea、number、color
- switch、select、multi-select、radio、checkbox
- image、datetime、daterange、slider、code
- image-list（多图上传）
- repeater（可重复字段）

如果使用不支持的类型，后台会显示"不支持的字段类型: xxx"
```

**原则：使用前必须确认字段类型已在 FieldRenderer.vue 中实现。**

### 2.3 统一 Header 和 Footer

```html
<!-- 所有页面必须使用系统的 headerMenu 和 footerMenu -->
<body>
    {{ template "header" . }}
    <main>
        <!-- 页面内容 -->
    </main>
    {{ template "footer" . }}
</body>
```

**原则：主题中所有页面必须调用统一的 Header 和 Footer，避免重复代码和维护不一致。**

### 2.4 文章内容渲染

```html
<!-- ❌ 错误：直接输出原文 -->
<div class="article-content">{{ .Content }}</div>

<!-- ✅ 正确：使用markdownHTML函数渲染 -->
<div class="article-content">{{ .Content | markdownHTML }}</div>
```

**原则：文章内容必须通过 markdownHTML 或类似函数处理后再显示，否则用户看到的是源码。**

### 2.5 图片路径处理

```html
<!-- ❌ 错误：假设固定域名 -->
<img src="http://example.com/image.png">

<!-- ✅ 正确：使用相对路径或配置的URL -->
<img src="{{ getConfig "authorAvatar" "" }}">
```

**原则：所有图片路径应支持配置或使用相对路径。**

## 三、开发流程规范

### 3.1 开发前检查清单

- [ ] 确认使用的字段类型已注册
- [ ] 确认所有颜色使用CSS变量
- [ ] 确认没有硬编码文本
- [ ] 确认CSS动画关键帧完整
- [ ] 确认HTML结构完整

### 3.2 调试技巧

```bash
# 1. 查看Go模板错误日志
# Gin框架会在控制台输出类似以下错误：
# - function "xxx" not defined
# - can't evaluate field xxx in type xxx
# - expected end, found xxx

# 2. 检查配置是否正确加载
GET /api/themes/{slug}/config/full

# 3. 清除主题缓存
# 重启后端服务
```

### 3.3 CSS组织结构

```
assets/
├── css/
│   ├── base.css      # 通用样式、CSS变量、重置样式
│   ├── header.css    # 头部导航样式
│   ├── footer.css    # 页脚样式
│   ├── home.css      # 首页样式
│   ├── article.css   # 文章页样式
│   └── sidebar.css   # 侧边栏样式
└── js/
    └── main.js       # 通用脚本
```

**原则：CSS文件按功能模块组织，避免单个文件过大。**

## 四、常见错误对照表

| 错误现象 | 常见原因 | 解决方案 |
|---------|---------|---------|
| "不支持的字段类型" | 使用了未注册的字段类型 | 在FieldRenderer.vue中注册 |
| 后台配置不生效 | config和configDefinition不一致 | 确保两者的name匹配 |
| 模板显示源码 | 未使用markdownHTML处理 | 添加 `\| markdownHTML` |
| 轮播只显示第一张 | 动画作用在错误元素上 | 动画应作用于每个slide |
| 切换时显示纯色 | 没有设置背景色或背景与slide颜色不一致 | 设置正确的背景色 |
| 所有页面样式不一致 | 没有使用统一的header/footer | 调用系统的headerMenu/footerMenu |
| 配置显示"未命名分组" | 结构体缺少JSON标签 | 添加json标签 |

## 五、代码质量标准

### 5.1 必须测试的场景

1. **配置保存和读取**
   - 后台修改配置 → 前台刷新 → 配置生效

2. **文章内容渲染**
   - Markdown格式文章 → 前台显示为HTML

3. **轮播功能**
   - 上传多张图片 → 自动轮播 → 平滑过渡

4. **响应式布局**
   - 桌面端 → 平板端 → 移动端

### 5.2 上线前必查

- [ ] 所有CSS颜色使用变量
- [ ] 所有文本支持配置
- [ ] 没有硬编码的URL或路径
- [ ] HTML结构完整
- [ ] CSS动画完整
- [ ] 字段类型已注册
- [ ] 文章内容已渲染

---

## 六、原则总结

1. **配置优先**：所有可能变化的内容都必须可配置
2. **变量化**：所有颜色和字号必须使用CSS变量
3. **组件化**：重复使用的模块（header/footer/sidebar）必须统一
4. **验证**：每个新功能必须测试配置保存、读取、渲染完整流程
5. **完整性**：HTML结构和CSS动画必须完整

> 记住：如果用户可能想要修改它，它就不应该硬编码在模板中。
