## 一、架构问题

### 1.1 页面模板系统不完善

**当前状态：**
- 所有页面都硬编码使用 `page.html` 模板
- Page 模型有 `Template` 字段，但没有被使用
- 每个主题只有 1 个页面模板

**问题：**
- Blog 主题和企业主题使用相同的页面模板
- 企业主题无法创建产品列表、服务展示等特殊页面
- 页面模板与主题不匹配

**优化建议：**
- 修改 `pageShowHandler` 使用页面的 `Template` 字段
- 在 `theme.yml` 中定义主题可用的页面模板
- 管理后台添加模板选择下拉框
- 每个主题可以定义多个页面模板（如 `page-services.html`, `page-products.html`）

**示例：**
```
catter-blog/pages/
├── page.html          ← 默认页面
├── page-about.html    ← 关于页面
└── page-contact.html  ← 联系页面

enterprise-website/pages/
├── page.html          ← 默认页面
├── page-services.html ← 服务列表（图片卡片）
├── page-products.html ← 产品展示
└── page-team.html     ← 团队介绍
```

---

### 1.2 SEO 设置不完整

**当前状态：**
- 只有站点级别的 SEO 设置（`site_title`, `site_description`）
- 没有页面级别的 SEO 设置

**问题：**
- 每个页面/文章无法设置独立的 title、description、keywords
- 没有 Open Graph 标签（社交媒体分享）
- 没有 Twitter Card 标签
- 没有自动生成 sitemap.xml

**优化建议：**
- 添加页面级别的 SEO 设置：
  - `meta_title` - 页面标题（用于 SEO）
  - `meta_description` - 页面描述
  - `meta_keywords` - 关键词
- 添加 Open Graph 支持：
  - `og:title`
  - `og:description`
  - `og:image`
  - `og:url`
- 添加 Twitter Card 支持
- 实现 sitemap.xml 自动生成

---

### 1.3 系统设置和主题配置重复

**当前状态：**
- 系统设置有：`site_title`, `site_description`
- 主题配置有：`config.siteTitle`, `config.siteDescription`

**问题：**
- 同样的设置在两个地方都有
- 修改系统设置后，主题配置不会同步
- 用户不知道应该在哪里修改

**优化建议：**
- 统一由系统设置管理站点信息
- 主题配置只管理外观相关（颜色、字体、模块开关）
- 移除主题配置中的重复项

**职责划分：**
```
系统设置 (settings)：
├── site_title          ← 站点标题
├── site_description    ← 站点描述
├── site_url            ← 站点URL
├── logo                ← 站点Logo
├── favicon             ← 网站图标
├── active_theme        ← 当前主题
└── posts_per_page      ← 每页文章数

主题配置 (theme_configs)：
├── appearance.colors   ← 颜色配置
├── appearance.typography ← 字体配置
├── modules.hero        ← Hero模块开关
├── widgets.author      ← 作者信息开关
└── custom.css/js       ← 自定义代码
```

---

### 1.4 主题配置过于复杂

**当前状态：**
- `theme.yml` 中的 `configDefinition` 定义了很多配置项
- 很多配置项（如颜色）实际上很少修改

**问题：**
- 配置项太多，用户不知道每个的作用
- 维护成本高
- 容易出错

**优化建议：**
- 简化 `theme.yml`，只保留必要的配置项
- 将不常用的配置项移到"高级设置"
- 提供预设的颜色方案，减少自定义需求

---

### 1.5 Logo 和 Banner 设置缺失

**当前状态：**
- 系统设置中有 `logo` 和 `favicon` 字段，但默认为空字符串
- 管理后台没有 Logo 上传界面
- 所有主题都使用文字 Logo（`{{ .site.title }}`）
- 没有 Banner/头部图片设置

**问题：**
- 用户无法上传自定义 Logo 图片
- 无法设置 Banner/头部背景图片
- Hero 模块只支持颜色背景，不支持图片背景

**当前 Logo 使用方式：**
```html
<!-- catter-blog -->
<a href="/" class="logo">{{ .site.title }}</a>

<!-- catter-cms-official -->
<a href="/" class="logo">{{ .site.title }}<span>CMS</span></a>

<!-- enterprise-website -->
<a href="/" class="brand">{{ .site.title }}<span>.</span></a>
```

**优化建议：**
- 在系统设置中添加 Logo 上传功能
- 修改 `getSiteData()` 返回 logo URL
- 模板中添加条件判断：有 Logo 图片则显示图片，否则显示文字
- 在主题配置中添加 Banner 图片设置（Hero 模块支持图片背景）

**需要修改的文件：**
- `admin/src/views/settings/SiteSettings.vue` - 添加 Logo 上传界面
- `gin-app/cmd/main.go` - `getSiteData()` 返回 logo
- `templates/themes/*/pages/*.html` - 模板支持图片 Logo
- `templates/themes/*/theme.yml` - 添加 Banner 图片配置

## 二、模板问题

### 2.1 样式内联

**当前状态：**
- 很多样式是内联在模板中的 `<style>` 标签
- 每个模板都重复定义相同的样式

**问题：**
- 模板文件臃肿
- 样式难以维护
- 无法复用

**优化建议：**
- 提取公共样式到 CSS 文件
- 模板只保留页面特定的样式
- 使用 CSS 变量统一管理颜色

**示例：**
```
catter-blog/assets/
├── css/
│   ├── common.css      ← 公共样式
│   ├── header.css      ← 头部样式
│   ├── footer.css      ← 底部样式
│   └── page.css        ← 页面样式
└── js/
    └── main.js
```

---

### 2.2 模板语法不统一

**当前状态：**
- catter-blog 使用 `{{ getConfig "key" "default" }}`
- catter-cms-official 使用 `{{ .modules.hero.config.title }}`
- enterprise-website 使用 `{{ .modules.hero.config.title }}`

**问题：**
- 不同主题使用不同的语法
- 维护困难
- 容易出错

**优化建议：**
- 统一使用 `getConfig` 函数
- 提供统一的模板语法文档

## 三、功能问题

### 3.1 菜单系统

**当前状态：**
- 菜单和页面是分离的
- 菜单只存储链接和标签
- 需要先创建页面，再创建菜单指向该页面

**问题：**
- 用户需要手动关联菜单和页面
- 容易出现 404 错误（菜单指向不存在的页面）

**优化建议：**
- 在创建菜单时，提供页面选择器
- 自动验证菜单链接是否有效
- 提供菜单模板（预设的菜单结构）

---

### 3.2 主题切换

**当前状态：**
- 切换主题后，菜单数据保留
- 但菜单链接可能指向新主题不存在的页面

**问题：**
- 切换主题后可能出现 404
- 需要手动调整菜单

**优化建议：**
- 切换主题时，检查菜单链接的有效性
- 提供菜单迁移工具
- 每个主题提供默认菜单配置

## 四、待讨论问题

### 4.1 页面模板选择机制

**问题：**
- 页面模板应该在创建页面时选择，还是在主题配置中定义？
- 如果切换主题，页面模板如何处理？

**方案A：页面绑定模板**
- 创建页面时选择模板
- 切换主题后，页面尝试使用同名模板
- 如果模板不存在，使用默认模板

**方案B：主题定义模板**
- 主题定义可用的页面模板
- 页面只存储内容，不存储模板名
- 渲染时由主题决定使用哪个模板

**建议：** 采用方案A，更灵活

## 五、管理后台问题

### 5.1 菜单管理数据加载失败

**当前状态：**
- 菜单管理界面完整，支持拖拽排序、多级菜单
- 链接类型选择（页面/分类/文章）的 UI 已实现
- 但选择后没有数据可供选择

**问题原因：**
- API 返回格式不匹配

```javascript
// 前端期望
pages.value = res.data?.data || []

// 后端实际返回
{
  "data": {
    "list": [...],  // ← 用的是 "list"，不是 "data"
    "total": 10
  }
}
```

- 参数名不匹配：前端使用 `per_page`，后端期望 `page_size`

**需要修复：**
- 统一 API 返回格式（使用 `list` 或 `data`）
- 统一分页参数名（`per_page` 或 `page_size`）

---

### 5.2 菜单图标选择器缺失

**当前状态：**
- 图标字段只是手动输入框
- 用户需要知道 Element Plus 图标名称才能使用
- 没有图标选择器 UI

**优化建议：**
- 添加图标选择器组件
- 显示图标预览
- 支持搜索图标

---

### 5.3 文章标题重复显示

**当前状态：**
- `article_show.html` 模板中显示文章标题：`<h1>{{ .post.Title }}</h1>`
- 如果用户的 Markdown 内容以 `# 标题` 开头，渲染后会出现两个标题

**问题示例：**
```html
<header class="article-header">
    <h1>我的文章标题</h1>  <!-- 模板显示的标题 -->
</header>

<div class="article-content">
    <h1>我的文章标题</h1>  <!-- Markdown 内容中的标题 -->
    <p>正文内容...</p>
</div>
```

**优化建议：**
- 方案A：移除模板中的标题，让用户在内容中自己写标题
- 方案B：保留模板标题，提醒用户内容不要以 `# 标题` 开头
- 方案C：自动检测并移除内容中的第一个标题（如果与文章标题相同）

---

### 5.4 缺少富文本编辑器

**当前状态：**
- 文章和页面都使用 Markdown 编辑器（md-editor-v3）
- 没有 WYSIWYG 富文本编辑器

**问题：**
- 不熟悉 Markdown 的用户使用困难
- 无法所见即所得编辑

**优化建议：**
- 使用 TinyMCE 替换 Markdown 编辑器
- 或者提供 Markdown/WYSIWYG 双模式切换

---

### 5.5 媒体库与编辑器集成不足

**当前状态：**
- 媒体库功能完整（上传、浏览、筛选、预览、删除）
- 但文章/页面编辑器中只能直接上传图片
- 无法从媒体库中选择已有图片

**优化建议：**
- 在编辑器中添加"从媒体库选择"功能
- 打开媒体库对话框，选择后插入到内容中
