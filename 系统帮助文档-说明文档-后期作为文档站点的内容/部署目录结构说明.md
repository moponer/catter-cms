## 两种部署方案

### 方案一：独立部署（推荐）

将所有文件放在同一目录，不区分开发目录：

```
部署目录/
├── catter-cms.exe          # 从 gin-app/cmd/main.go 编译
├── config.yaml             # 配置文件
├── catter.db               # 数据库
├── uploads/                # 上传目录
├── admin/dist/             # 从 admin/ 构建复制
├── templates/              # 从 gin-app/templates/ 复制
│   ├── 404.html
│   └── themes/
└── public/                 # 可选
```

**优点：**
- 结构清晰，所有文件在一起
- 便于备份和迁移
- 路径配置简单（全部使用相对路径 `./`）

**构建步骤：**
```bash
# 1. 创建部署目录
mkdir -p /var/www/catter-cms

# 2. 编译后端
cd gin-app
go build -o ../catter-cms.exe ./cmd/main.go

# 3. 构建前端
cd admin
npm run build

# 4. 复制必要文件到部署目录
cp catter-cms.exe /var/www/catter-cms/
cp gin-app/config.yaml /var/www/catter-cms/
cp -r admin/dist /var/www/catter-cms/admin
cp -r gin-app/templates /var/www/catter-cms/
mkdir -p /var/www/catter-cms/uploads
```

### 方案二：开发目录直接运行（当前方式）

保持开发目录结构，从项目根目录运行：

```
Catter-CMS/                  # 项目根目录
├── catter-cms.exe          # 编译后的可执行文件
├── catter.db               # 数据库（根目录）
├── uploads/                # 上传目录（根目录）
├── admin/dist/             # 前端构建文件
├── gin-app/
│   ├── config.yaml         # 配置文件
│   └── templates/          # 模板和主题
│       ├── 404.html
│       └── themes/
└── ...
```

**需要修改的配置：**

1. **config.yaml** 路径：`./gin-app/config.yaml`
2. **admin/dist** 路径：`./admin/dist`
3. **templates** 路径：`./gin-app/templates`
4. **404.html** 路径：`./gin-app/templates/404.html`

### 建议的两种整理方式

#### 方式A：全部集中到根目录（推荐部署用）

```bash
# 创建统一的部署结构
Catter-CMS/
├── catter-cms.exe
```

修改代码中的所有路径为 `./` 开头：
- `./config.yaml`
- `./admin/dist`
- `./templates/404.html`

```bash

    ├── config.yaml
    ├── catter.db
    ├── uploads/

    └── templates/
```

## 生产环境部署清单

### 必需文件

| 文件/目录 | 来源 | 说明 |
|---------|------|------|
| catter-cms.exe | `go build` | 主程序 |
| config.yaml | 手动创建或复制 | 配置文件 |
| catter.db | 自动创建 | 数据库 |
| admin/dist/ | `npm run build` | 前端文件 |
| templates/404.html | 复制 | 错误页面 |
| templates/themes/ | 复制 | 主题文件 |
| uploads/ | 自动创建 | 上传目录 |

### 配置文件示例

```yaml
server:
  port: "3001"
  host: "0.0.0.0"
  mode: "release"

database:
  driver: "sqlite"
  database: "catter.db"      # 相对路径

jwt:
  secret: "your-strong-secret-key-here"
  expire: 24

upload:
  max_size: 10485760
  path: "uploads"            # 相对路径
  allowed_ext: ".jpg,.jpeg,.png,.gif,.webp"
```

## 推荐的最终结构

最简单的部署方式：

```
# 创建部署包
catter-cms-deployment/
├── catter-cms.exe
├── config.yaml
├── start.bat / start.sh    # 启动脚本
├── README.md
├── admin/
│   └── dist/
├── templates/
│   ├── 404.html
│   └── themes/
│       ├── catter-blog/
│       ├── catter-cms-official/
│       └── enterprise-website/
└── uploads/                # 首次启动自动创建
```

启动脚本 `start.bat`：
```batch
@echo off
cd /d "%~dp0"
catter-cms.exe
pause
```

启动脚本 `start.sh`：
```bash
#!/bin/bash
cd "$(dirname "$0")"
./catter-cms.exe
```

## 总结

1. **开发时**：保持现状，从 `Catter-CMS/` 目录运行 `catter-cms.exe`
2. **部署时**：建议将 `templates/` 从 `gin-app/` 移到根目录，使所有资源都在同一层级
3. **关键**：确保代码中的相对路径与实际目录结构匹配
